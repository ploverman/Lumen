Building the Lumen Installer

How to create LumenSetup.exe, a single-file installer for the Lumen app that does not include Lumen Viewer. No installer framework is involved: it is a small C# program with the app embedded as resources.

Already have the current source tree? Steps 1 to 8 are done there, so go to Step 9. The earlier steps show every file and explain it, so you can recreate or change the installer. The listings on this page are the actual source files.

Overview

The result is one exe. When it runs, it checks for .NET Framework 4.7, shows a window, copies the embedded Lumen files to a per-user folder, and registers the app with Windows. It also copies itself into that folder as uninstall.exe.

Design decisions

DecisionWhy
Target .NET 4.0, while Lumen targets 4.7A .NET 4.7 installer could not start on the machine it needs to warn. A 4.0 program runs on any 4.x runtime, so it can start and report what is missing.
WinForms, not WPFA small dialog needs nothing more, and it keeps the exe light.
Install per user, to %LOCALAPPDATA%\Programs\LumenEverything goes under the user's profile and HKEY_CURRENT_USER, so no administrator rights or UAC prompt are needed.
Embed one resource per fileThe folder structure survives in the resource names, no zip code is needed, and the exe stays a single file.
Write an install.manifest file listUninstall deletes only the listed files, so it can never destroy something a user put in that folder.
Share code with the viewer installerThe two installers differ only in a few names, which Product.cs holds. The Lumen project links the rest from src\Lumen.Setup.

What happens during a build

  1. MSBuild starts Lumen.DesktopSetup.csproj.
  2. A custom target runs before compilation and builds Lumen.Desktop, whose project references bring in the engine, visuals and other libraries.
  3. That target collects everything in src\Lumen.Desktop\bin\Release except symbols, and adds each file as an embedded resource named payload/<relative path>.
  4. The C# compiler builds LumenSetup.exe with those resources inside.

Lumen does not reference Lumen.Viewer, so the viewer can't reach the output folder. That is what keeps it out of this installer. Step 10 confirms it.

What you need

  • Visual Studio 2022 with the .NET desktop development workload. Use its MSBuild.exe, not dotnet build, as the rest of Lumen does.
  • The Lumen source tree, here E:\AAA\Claude\PowerClone\PRD. Run the commands below in PowerShell from that folder.
  • Network access on the first build, so that NuGet can restore packages. If the .NET 4.0 targeting pack isn't on the machine, restore also fetches its reference assemblies.

Step 2: Add the manifest

Save this as src\Lumen.Setup\app.manifest. Two settings matter:

  • asInvoker runs the program with the user's normal rights. Without it, Windows sees "Setup" in the file name and demands elevation. This is called installer detection.
  • dpiAware keeps text sharp on scaled displays. It also makes the program responsible for its own layout scaling, which Step 6 handles.
<?xml version="1.0" encoding="utf-8"?>
<assembly manifestVersion="1.0" xmlns="urn:schemas-microsoft-com:asm.v1">
  <assemblyIdentity version="1.0.0.0" name="Lumen.Setup" />
  <!-- The install is per user. asInvoker also stops Windows from demanding elevation because "Setup" is in the file name. -->
  <trustInfo xmlns="urn:schemas-microsoft-com:asm.v3">
    <security>
      <requestedPrivileges>
        <requestedExecutionLevel level="asInvoker" uiAccess="false" />
      </requestedPrivileges>
    </security>
  </trustInfo>
  <application xmlns="urn:schemas-microsoft-com:asm.v3">
    <windowsSettings>
      <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true</dpiAware>
    </windowsSettings>
  </application>
</assembly>

Step 3: Describe the product

Save this as src\Lumen.DesktopSetup\Product.cs. The shared code reads every product-specific name from this class. These values are const, so the shared code can use them to build its own constants.

The ProgId and RegistryKey must differ from the viewer's values. That is why the two products can be installed and removed independently.

namespace Lumen.Setup
{
    /// <summary>What this installer installs. Each setup project has its own copy of this class and shares the rest of the code, so the two products register under different names and can sit side by side.</summary>
    internal static class Product
    {
        /// <summary>The name people see, and the install folder, shortcut and Settings entry.</summary>
        public const string Name = "Lumen";
        /// <summary>The application's exe.</summary>
        public const string ExeName = "Lumen.exe";
        /// <summary>The shortcut's tooltip.</summary>
        public const string Description = "Build and share Lumen reports";
        /// <summary>The file type registration for .lumen files.</summary>
        public const string ProgId = "Lumen.Report";
        /// <summary>The key under the Windows Uninstall list.</summary>
        public const string RegistryKey = "Lumen";
    }
}

Step 4: Write the install logic

Save this as src\Lumen.Setup\Installer.cs. It has three classes:

ClassJob
InstallOptionsPlain settings that the window and the command line both fill.
DotNetThe prerequisite check.
InstallerCopying, shortcuts, file association, the Settings entry, and uninstall.

The .NET check

.NET Framework 4.5 and later publish a Release DWORD under HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full. Compare it with >=, because later versions have higher numbers. Microsoft documents 460798 as the lowest value for 4.7.

The exe is AnyCPU, so it could run as a 32-bit process, and the code opens the 64-bit registry view explicitly. Meets47 is a pure function of the number, which lets the /assumerelease switch test it on any machine.

Points worth reading in the code

  • Upgrade: Install compares the old manifest with the new list and deletes files that the new version no longer ships.
  • Failure: a failed first install removes what it wrote. The catch ... when (!upgrade) filter leaves a failed upgrade in place, and running setup again repairs it.
  • Self-delete: a running exe can't delete itself, so Uninstall starts a hidden cmd.exe that waits about two seconds, then deletes uninstall.exe and removes the folder if it's empty.
  • Shortcuts: these go through the WScript.Shell COM object with dynamic, which is why the project references Microsoft.CSharp.
  • File association: Associate sets itself as the default only when .lumen has no owner. Otherwise it joins OpenWithProgids, so it never takes the default from another app.
Show Installer.cs 
using System;
using System.Collections.Generic;
using System.Diagnostics;
using System.IO;
using System.Linq;
using System.Reflection;
using System.Runtime.InteropServices;
using Microsoft.Win32;

namespace Lumen.Setup
{
    /// <summary>What a run of the installer should do. The form and the command line both fill one of these.</summary>
    internal sealed class InstallOptions
    {
        /// <summary>Install folder.</summary>
        public string Folder = Installer.DefaultFolder;
        /// <summary>Add a desktop shortcut.</summary>
        public bool DesktopShortcut;
        /// <summary>Make the application open .lumen files.</summary>
        public bool Associate = true;
    }

    /// <summary>The prerequisite check. .NET Framework 4.x reports its version as a number in the registry; Microsoft documents 460798 as the lowest value for 4.7.</summary>
    internal static class DotNet
    {
        /// <summary>The lowest Release value of .NET Framework 4.7.</summary>
        public const int Net47Release = 460798;
        /// <summary>Where to get it. The installer opens this page; it never downloads anything itself.</summary>
        public const string DownloadUrl = "https://dotnet.microsoft.com/download/dotnet-framework/net47";

        /// <summary>The installed Release value, or 0 if .NET 4.5 or later is absent. Reads the 64-bit view, which a 32-bit process would otherwise not see.</summary>
        public static int InstalledRelease()
        {
            var view = Environment.Is64BitOperatingSystem ? RegistryView.Registry64 : RegistryView.Registry32;
            using (var hklm = RegistryKey.OpenBaseKey(RegistryHive.LocalMachine, view))
            using (var key = hklm.OpenSubKey(@"SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full"))
                return key?.GetValue("Release") is int release ? release : 0;
        }

        /// <summary>True when the machine can run the application. Pure, so that the self-test can drive it with any number.</summary>
        public static bool Meets47(int release) => release >= Net47Release;
    }

    /// <summary>Copies the embedded application and registers it for the current user. Everything lands under the user's profile and HKEY_CURRENT_USER, so no administrator rights are needed.</summary>
    internal static class Installer
    {
        private const string AppName = Product.Name;
        private const string ExeName = Product.ExeName;
        private const string UninstallerName = "uninstall.exe";
        // Lists the installed files, one relative path per line. The uninstaller deletes these and nothing else, so a folder the user chose is safe.
        private const string ManifestName = "install.manifest";
        private const string PayloadPrefix = "payload/";
        private const string ProgId = Product.ProgId;
        private const string UninstallKey = @"Software\Microsoft\Windows\CurrentVersion\Uninstall\" + Product.RegistryKey;
        private const string ClassesKey = @"Software\Classes\";

        /// <summary>The usual place for a per-user application.</summary>
        public static string DefaultFolder => Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData), "Programs", AppName);

        private static string StartMenuLink => Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.Programs), AppName + ".lnk");
        private static string DesktopLink => Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.DesktopDirectory), AppName + ".lnk");

        /// <summary>The installer's version, which the build takes from Directory.Build.props.</summary>
        public static string Version => Assembly.GetExecutingAssembly().GetName().Version.ToString(3);

        /// <summary>The embedded files.</summary>
        private static List<string> Payload() =>
            Assembly.GetExecutingAssembly().GetManifestResourceNames().Where(n => n.StartsWith(PayloadPrefix, StringComparison.Ordinal)).ToList();

        /// <summary>True if the application started from this folder is running. Windows would refuse to overwrite or delete its files.</summary>
        public static bool AppRunning(string folder)
        {
            string exe = Path.Combine(folder, ExeName);
            foreach (var p in Process.GetProcessesByName(Path.GetFileNameWithoutExtension(ExeName)))
            {
                using (p)
                {
                    try { if (string.Equals(p.MainModule.FileName, exe, StringComparison.OrdinalIgnoreCase)) return true; }
                    catch (Exception ex) when (ex is System.ComponentModel.Win32Exception || ex is InvalidOperationException) { }
                }
            }
            return false;
        }

        /// <summary>Installs or upgrades. <paramref name="progress"/> gets a percentage. A failed first install removes what it wrote; a failed upgrade leaves a mix, and running setup again repairs it.</summary>
        public static void Install(InstallOptions o, Action<int> progress)
        {
            string folder = Path.GetFullPath(o.Folder);
            string manifest = Path.Combine(folder, ManifestName);
            bool upgrade = File.Exists(manifest);
            var previous = upgrade ? File.ReadAllLines(manifest).ToList() : new List<string>();
            var written = new List<string>();
            var payload = Payload();
            try
            {
                Directory.CreateDirectory(folder);
                var assembly = Assembly.GetExecutingAssembly();
                for (int i = 0; i < payload.Count; i++)
                {
                    string relative = payload[i].Substring(PayloadPrefix.Length).Replace('/', Path.DirectorySeparatorChar);
                    string target = Path.Combine(folder, relative);
                    Directory.CreateDirectory(Path.GetDirectoryName(target));
                    using (var from = assembly.GetManifestResourceStream(payload[i]))
                    using (var to = new FileStream(target, FileMode.Create, FileAccess.Write))
                        from.CopyTo(to);
                    written.Add(relative);
                    progress((i + 1) * 90 / payload.Count);
                }
                File.Copy(Assembly.GetExecutingAssembly().Location, Path.Combine(folder, UninstallerName), true);
                written.Add(UninstallerName);
                written.Add(ManifestName);
                File.WriteAllLines(manifest, written);

                // Files of an older version that this one no longer ships.
                foreach (var stale in previous.Except(written, StringComparer.OrdinalIgnoreCase))
                    DeleteFile(Path.Combine(folder, stale));

                string exe = Path.Combine(folder, ExeName);
                CreateShortcut(StartMenuLink, exe, folder);
                if (o.DesktopShortcut) CreateShortcut(DesktopLink, exe, folder);
                if (o.Associate) Associate(exe);
                Register(folder, exe);
                progress(100);
            }
            catch (Exception) when (!upgrade)
            {
                foreach (var f in written) DeleteFile(Path.Combine(folder, f));
                RemoveEmptyFolders(folder, written);
                throw;
            }
        }

        /// <summary>Removes what <see cref="Install"/> added, running from the installed uninstall.exe. That exe cannot delete itself while it runs, so a hidden command finishes the job after it exits.</summary>
        public static void Uninstall(string folder)
        {
            var listed = File.ReadAllLines(Path.Combine(folder, ManifestName)).ToList();
            DeleteFile(StartMenuLink);
            DeleteFile(DesktopLink);
            Unassociate();
            Registry.CurrentUser.DeleteSubKeyTree(UninstallKey, false);
            foreach (var f in listed.Where(x => !x.Equals(UninstallerName, StringComparison.OrdinalIgnoreCase)))
                DeleteFile(Path.Combine(folder, f));
            RemoveEmptyFolders(folder, listed);

            string me = Path.Combine(folder, UninstallerName);
            string command = "/c ping -n 3 127.0.0.1 >nul & del /f /q \"" + me + "\" & rmdir \"" + folder + "\"";
            Process.Start(new ProcessStartInfo("cmd.exe", command) { CreateNoWindow = true, UseShellExecute = false });
        }

        /// <summary>Starts the installed application.</summary>
        public static void Launch(string folder) => Process.Start(Path.Combine(folder, ExeName));

        /// <summary>Deletes a file that may already be gone.</summary>
        private static void DeleteFile(string path)
        {
            if (File.Exists(path)) File.Delete(path);
        }

        /// <summary>Removes the subfolders of the listed files, deepest first, then the install folder, if each is empty. Never recursive: a file the user put there stays.</summary>
        private static void RemoveEmptyFolders(string folder, IEnumerable<string> files)
        {
            var folders = files.Select(Path.GetDirectoryName).Where(d => !string.IsNullOrEmpty(d)).Distinct().OrderByDescending(d => d.Length)
                .Select(d => Path.Combine(folder, d)).Concat(new[] { folder });
            foreach (var d in folders)
                if (Directory.Exists(d) && !Directory.EnumerateFileSystemEntries(d).Any()) Directory.Delete(d);
        }

        /// <summary>Makes a .lnk through the shell's scripting object, which is the one way to write one from managed code without a type library reference.</summary>
        private static void CreateShortcut(string link, string target, string folder)
        {
            dynamic shell = Activator.CreateInstance(Type.GetTypeFromProgID("WScript.Shell"));
            dynamic shortcut = shell.CreateShortcut(link);
            shortcut.TargetPath = target;
            shortcut.WorkingDirectory = folder;
            shortcut.Description = Product.Description;
            shortcut.Save();
            Marshal.FinalReleaseComObject(shortcut);
            Marshal.FinalReleaseComObject(shell);
        }

        /// <summary>Registers the file type. If something else already owns .lumen it stays the default, and this application joins Open with.</summary>
        private static void Associate(string exe)
        {
            var hkcu = Registry.CurrentUser;
            using (var command = hkcu.CreateSubKey(ClassesKey + ProgId + @"\shell\open\command"))
                command.SetValue("", "\"" + exe + "\" \"%1\"");
            using (var type = hkcu.CreateSubKey(ClassesKey + ProgId))
                type.SetValue("", "Lumen report");
            using (var icon = hkcu.CreateSubKey(ClassesKey + ProgId + @"\DefaultIcon"))
                icon.SetValue("", exe + ",0");
            using (var ext = hkcu.CreateSubKey(ClassesKey + ".lumen"))
            {
                if (string.IsNullOrEmpty(ext.GetValue("") as string)) ext.SetValue("", ProgId);
                using (var with = ext.CreateSubKey("OpenWithProgids")) with.SetValue(ProgId, "");
            }
            NotifyShell();
        }

        /// <summary>Undoes <see cref="Associate"/>, leaving anything another program registered.</summary>
        private static void Unassociate()
        {
            var hkcu = Registry.CurrentUser;
            hkcu.DeleteSubKeyTree(ClassesKey + ProgId, false);
            bool remove = false;
            using (var ext = hkcu.OpenSubKey(ClassesKey + ".lumen", true))
            {
                if (ext != null)
                {
                    if (ext.GetValue("") as string == ProgId) ext.DeleteValue("");
                    using (var with = ext.OpenSubKey("OpenWithProgids", true))
                    {
                        with?.DeleteValue(ProgId, false);
                        if (with != null && with.ValueCount == 0) ext.DeleteSubKey("OpenWithProgids");
                    }
                    remove = ext.ValueCount == 0 && ext.SubKeyCount == 0;
                }
            }
            if (remove) hkcu.DeleteSubKey(ClassesKey + ".lumen");
            NotifyShell();
        }

        /// <summary>Adds the entry in Settings, Installed apps.</summary>
        private static void Register(string folder, string exe)
        {
            string uninstaller = "\"" + Path.Combine(folder, UninstallerName) + "\" /uninstall";
            long kb = Directory.GetFiles(folder, "*", SearchOption.AllDirectories).Sum(f => new FileInfo(f).Length) / 1024;
            using (var key = Registry.CurrentUser.CreateSubKey(UninstallKey))
            {
                key.SetValue("DisplayName", AppName);
                key.SetValue("DisplayVersion", Version);
                key.SetValue("Publisher", "Lumen");
                key.SetValue("InstallLocation", folder);
                key.SetValue("DisplayIcon", exe);
                key.SetValue("UninstallString", uninstaller);
                key.SetValue("QuietUninstallString", uninstaller + " /quiet");
                key.SetValue("NoModify", 1, RegistryValueKind.DWord);
                key.SetValue("NoRepair", 1, RegistryValueKind.DWord);
                key.SetValue("EstimatedSize", (int)kb, RegistryValueKind.DWord);
            }
        }

        /// <summary>Tells Explorer that file associations changed, so icons update without a restart.</summary>
        private static void NotifyShell() => SHChangeNotify(0x08000000, 0, IntPtr.Zero, IntPtr.Zero);

        [DllImport("shell32.dll")] private static extern void SHChangeNotify(int eventId, uint flags, IntPtr item1, IntPtr item2);
    }
}

Step 5: Write the entry point

Save this as src\Lumen.Setup\Program.cs. The same exe plays three parts, chosen by the command line:

  • No arguments: it shows the setup window.
  • /quiet: it installs with no window and reports through the exit code.
  • /uninstall: it removes the app. Install copied the running exe to uninstall.exe, and Windows Settings calls it with this switch.
Show Program.cs 
using System;
using System.Diagnostics;
using System.IO;
using System.Linq;
using System.Windows.Forms;

namespace Lumen.Setup
{
    /// <summary>Entry point. With no arguments it shows the setup window. Run as uninstall.exe with /uninstall it removes the application.
    /// <para>Command line: <c>/quiet</c> shows no window; <c>/dir=path</c>, <c>/desktop</c> and <c>/noassoc</c> set the options;
    /// <c>/assumerelease=n</c> pretends the machine reports .NET Release n, to test the prerequisite check.</para>
    /// <para>Exit codes: 0 done, 1 failed, 2 .NET Framework 4.7 is missing, 3 the application is running.</para></summary>
    internal static class Program
    {
        private const int Failed = 1, MissingDotNet = 2, AppRunning = 3;

        /// <summary>Routes the command line.</summary>
        [STAThread]
        private static int Main(string[] args)
        {
            Application.EnableVisualStyles();
            Application.SetCompatibleTextRenderingDefault(false);
            bool quiet = Has(args, "/quiet");
            if (Has(args, "/uninstall")) return Uninstall(quiet);

            string assumed = Value(args, "/assumerelease=");
            int release = assumed != null ? int.Parse(assumed) : DotNet.InstalledRelease();
            if (!Environment.Is64BitOperatingSystem)
            {
                if (!quiet) MessageBox.Show(Product.Name + " needs 64-bit Windows.", Product.Name + " Setup", MessageBoxButtons.OK, MessageBoxIcon.Error);
                return Failed;
            }

            var options = new InstallOptions
            {
                Folder = Value(args, "/dir=") ?? Installer.DefaultFolder,
                DesktopShortcut = Has(args, "/desktop"),
                Associate = !Has(args, "/noassoc")
            };
            if (!quiet)
            {
                Application.Run(new SetupForm(options, release));
                return 0;
            }

            if (!DotNet.Meets47(release)) return MissingDotNet;
            if (Installer.AppRunning(Path.GetFullPath(options.Folder))) return AppRunning;
            try { Installer.Install(options, p => { }); return 0; }
            catch (Exception ex) when (IsExpected(ex)) { Console.Error.WriteLine(ex.Message); return Failed; }
        }

        /// <summary>Removes the application in the folder this exe runs from.</summary>
        private static int Uninstall(bool quiet)
        {
            string folder = Path.GetDirectoryName(Process.GetCurrentProcess().MainModule.FileName);
            if (Installer.AppRunning(folder))
            {
                if (!quiet) MessageBox.Show("Close " + Product.Name + ", then uninstall again.", Product.Name, MessageBoxButtons.OK, MessageBoxIcon.Warning);
                return AppRunning;
            }
            if (!quiet && MessageBox.Show("Remove " + Product.Name + "? Your reports are not touched.", Product.Name, MessageBoxButtons.YesNo, MessageBoxIcon.Question) != DialogResult.Yes) return 0;
            try { Installer.Uninstall(folder); return 0; }
            catch (Exception ex) when (IsExpected(ex))
            {
                if (!quiet) MessageBox.Show("Could not remove everything: " + ex.Message, Product.Name, MessageBoxButtons.OK, MessageBoxIcon.Error);
                return Failed;
            }
        }

        /// <summary>The failures a full disk, a locked file or a bad path can cause.</summary>
        internal static bool IsExpected(Exception ex) => ex is IOException || ex is UnauthorizedAccessException || ex is ArgumentException || ex is NotSupportedException;

        private static bool Has(string[] args, string flag) => args.Any(a => a.Equals(flag, StringComparison.OrdinalIgnoreCase));

        private static string Value(string[] args, string prefix) =>
            args.Where(a => a.StartsWith(prefix, StringComparison.OrdinalIgnoreCase)).Select(a => a.Substring(prefix.Length)).FirstOrDefault();
    }
}

Step 6: Write the setup window

Save this as src\Lumen.Setup\SetupForm.cs. The UI is built in code, with no designer file, as in the rest of Lumen. Three details matter:

  • Missing .NET: the input controls are disabled and the main button becomes Get .NET 4.7, which opens Microsoft's page. The installer never downloads anything itself.
  • Threading: installing runs on a worker thread so that the progress bar moves, and it returns to the UI thread through BeginInvoke. FormClosing refuses to close while _busy is set.
  • Display scaling: the layout is in 96 dpi pixels, while fonts in points grow with the display. The last line of the constructor calls Scale with the real dpi. Leave AutoScaleMode at None: with Dpi, this window grew but its controls didn't, and the .NET message was cut off at 125%.
Show SetupForm.cs 
using System;
using System.Diagnostics;
using System.Drawing;
using System.IO;
using System.Threading;
using System.Windows.Forms;

namespace Lumen.Setup
{
    /// <summary>The one setup window: folder, options, prerequisite status and progress. With .NET 4.7 missing, Install is replaced by a link to Microsoft's download page.</summary>
    internal sealed class SetupForm : Form
    {
        private readonly InstallOptions _options;
        private readonly bool _dotNetOk;
        private readonly TextBox _folder = new TextBox { Left = 16, Top = 72, Width = 372 };
        private readonly Button _browse = new Button { Text = "Browse...", Left = 396, Top = 70, Width = 84, Height = 26 };
        private readonly CheckBox _associate = new CheckBox { Text = "Open .lumen files with " + Product.Name, Left = 16, Top = 108, Width = 460 };
        private readonly CheckBox _desktop = new CheckBox { Text = "Add a desktop shortcut", Left = 16, Top = 134, Width = 460 };
        private readonly CheckBox _launch = new CheckBox { Text = "Start " + Product.Name + " now", Left = 16, Top = 134, Width = 460, Checked = true, Visible = false };
        private readonly Label _status = new Label { Left = 16, Top = 168, Width = 464, Height = 36 };
        private readonly ProgressBar _bar = new ProgressBar { Left = 16, Top = 208, Width = 464, Height = 16 };
        private readonly Button _action = new Button { Left = 300, Top = 238, Width = 88, Height = 28 };
        private readonly Button _close = new Button { Text = "Cancel", Left = 392, Top = 238, Width = 88, Height = 28 };
        private bool _finished, _busy;

        /// <summary>Builds the window. <paramref name="release"/> is the .NET Release value found on the machine.</summary>
        public SetupForm(InstallOptions options, int release)
        {
            _options = options;
            _dotNetOk = DotNet.Meets47(release);
            Text = Product.Name + " " + Installer.Version + " Setup";
            ClientSize = new Size(496, 280);
            FormBorderStyle = FormBorderStyle.FixedDialog;
            MaximizeBox = false;
            StartPosition = FormStartPosition.CenterScreen;
            AutoScaleMode = AutoScaleMode.None;
            Font = new Font("Segoe UI", 9f);

            Controls.Add(new Label { Text = Product.Name, Left = 16, Top = 12, Width = 464, Height = 28, Font = new Font("Segoe UI", 14f, FontStyle.Bold) });
            Controls.Add(new Label { Text = "Install to this folder. No administrator rights are needed.", Left = 16, Top = 48, Width = 464 });
            _folder.Text = options.Folder;
            _associate.Checked = options.Associate;
            _desktop.Checked = options.DesktopShortcut;
            Controls.AddRange(new Control[] { _folder, _browse, _associate, _desktop, _launch, _status, _bar, _action, _close });

            _status.Text = _dotNetOk ? ".NET Framework 4.7 or later is installed."
                : Product.Name + " needs .NET Framework 4.7 or later, and this PC does not have it. Install it from Microsoft, restart if asked, then run this setup again.";
            _status.ForeColor = _dotNetOk ? SystemColors.ControlText : Color.Firebrick;
            _action.Text = _dotNetOk ? "Install" : "Get .NET 4.7";
            _folder.Enabled = _browse.Enabled = _associate.Enabled = _desktop.Enabled = _dotNetOk;

            _browse.Click += (s, e) => Browse();
            _action.Click += (s, e) => { if (_dotNetOk) Run(); else Process.Start(DotNet.DownloadUrl); };
            _close.Click += (s, e) => Close();
            FormClosing += (s, e) => { e.Cancel = _busy; };
            FormClosed += (s, e) => { if (_finished && _launch.Checked) Installer.Launch(_options.Folder); };
            AcceptButton = _action;
            ActiveControl = _action;
            // The layout above is in 96 dpi pixels, while fonts in points already follow the display.
            using (var g = CreateGraphics()) Scale(new SizeF(g.DpiX / 96f, g.DpiY / 96f));
        }

        /// <summary>Picks the install folder.</summary>
        private void Browse()
        {
            using (var dlg = new FolderBrowserDialog { SelectedPath = _folder.Text })
                if (dlg.ShowDialog(this) == DialogResult.OK) _folder.Text = dlg.SelectedPath;
        }

        /// <summary>Installs on a worker thread, so that the window stays live and the bar moves.</summary>
        private void Run()
        {
            _options.Folder = _folder.Text.Trim();
            _options.Associate = _associate.Checked;
            _options.DesktopShortcut = _desktop.Checked;
            string folder;
            try { folder = Path.GetFullPath(_options.Folder); }
            catch (Exception ex) when (Program.IsExpected(ex)) { Report("That folder is not valid: " + ex.Message); return; }
            if (Installer.AppRunning(folder)) { Report("Close " + Product.Name + ", then press Install again."); return; }

            _busy = true;
            _action.Enabled = _close.Enabled = _folder.Enabled = _browse.Enabled = _associate.Enabled = _desktop.Enabled = false;
            _status.ForeColor = SystemColors.ControlText;
            _status.Text = "Installing...";
            new Thread(() =>
            {
                try
                {
                    Installer.Install(_options, p => BeginInvoke(new Action(() => _bar.Value = p)));
                    BeginInvoke(new Action(Finished));
                }
                catch (Exception ex) when (Program.IsExpected(ex))
                {
                    BeginInvoke(new Action(() =>
                    {
                        _busy = false;
                        _action.Enabled = _close.Enabled = _folder.Enabled = _browse.Enabled = _associate.Enabled = _desktop.Enabled = true;
                        Report("Setup could not finish: " + ex.Message);
                    }));
                }
            }) { IsBackground = false }.Start();
        }

        /// <summary>Shows a problem in the status line.</summary>
        private void Report(string text)
        {
            _status.ForeColor = Color.Firebrick;
            _status.Text = text;
        }

        /// <summary>Turns the window into its last page.</summary>
        private void Finished()
        {
            _busy = false;
            _finished = true;
            _status.Text = Product.Name + " is installed. Find it on the Start menu.";
            _desktop.Visible = false;
            _launch.Visible = true;
            _action.Visible = false;
            _close.Text = "Finish";
            _close.Enabled = true;
            AcceptButton = _close;
        }
    }
}

Step 7: Write the project file

Save this as src\Lumen.DesktopSetup\Lumen.DesktopSetup.csproj. This file is what makes the installer. An installer written for another app would change little else.

<Project Sdk="Microsoft.NET.Sdk">
  <!-- The installer for the Lumen builder. It compiles the code of Lumen.Setup with its own Product.cs, and embeds Lumen.Desktop instead of the viewer. It targets .NET 4.0 for the same reason: to start without 4.7 and say what is missing. -->
  <PropertyGroup>
    <TargetFramework>net40</TargetFramework>
    <OutputType>WinExe</OutputType>
    <AssemblyName>LumenSetup</AssemblyName>
    <RootNamespace>Lumen.Setup</RootNamespace>
    <PlatformTarget>AnyCPU</PlatformTarget>
    <ApplicationManifest>..\Lumen.Setup\app.manifest</ApplicationManifest>
    <StartupObject>Lumen.Setup.Program</StartupObject>
    <EnableDefaultEmbeddedResourceItems>false</EnableDefaultEmbeddedResourceItems>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="System.Windows.Forms" />
    <Reference Include="System.Drawing" />
    <Reference Include="Microsoft.CSharp" />
    <Compile Include="..\Lumen.Setup\Installer.cs" Link="Installer.cs" />
    <Compile Include="..\Lumen.Setup\Program.cs" Link="Program.cs" />
    <Compile Include="..\Lumen.Setup\SetupForm.cs" Link="SetupForm.cs" />
  </ItemGroup>

  <!-- Restores and builds Lumen, then embeds its output as one resource per file, named payload/<relative path>. Symbols stay out.
       The restore has its own property so that MSBuild evaluates the project afresh for the build, with the restored packages. -->
  <Target Name="EmbedApp" BeforeTargets="BeforeBuild">
    <MSBuild Projects="..\Lumen.Desktop\Lumen.Desktop.csproj" Targets="Restore" Properties="Configuration=$(Configuration);MSBuildRestoreSessionId=$([System.Guid]::NewGuid())" />
    <MSBuild Projects="..\Lumen.Desktop\Lumen.Desktop.csproj" Properties="Configuration=$(Configuration)" />
    <PropertyGroup>
      <AppOut>..\Lumen.Desktop\bin\$(Configuration)\</AppOut>
    </PropertyGroup>
    <ItemGroup>
      <AppFile Include="$(AppOut)**\*" Exclude="$(AppOut)**\*.pdb" />
      <EmbeddedResource Include="@(AppFile)" LogicalName="payload/%(RecursiveDir)%(Filename)%(Extension)" Type="Non-Resx" WithCulture="false" />
    </ItemGroup>
  </Target>
</Project>
SettingWhy
TargetFramework and PlatformTargetThese override net47 and x64 from Directory.Build.props. The project file wins because it's evaluated after that file.
AssemblyNameThis names the output LumenSetup.exe.
RootNamespaceThe shared code lives in namespace Lumen.Setup, so Product.cs uses it too.
EnableDefaultEmbeddedResourceItemsThis stops the SDK from adding its own resources, so the only ones are those the target adds.
<Compile Include ... Link>These compile the shared files in place, without copying them. Product.cs needs no entry, because the SDK picks up .cs files in the project's own folder.
BeforeTargets="BeforeBuild"The target must run before compilation, so that the resources are there for the compiler.
<MSBuild Projects=...>These are build calls, not a ProjectReference. A reference to a net47 project from a net40 one would be rejected, and it would also copy Lumen's files beside the installer.
Targets="Restore" and MSBuildRestoreSessionIdThe -restore switch restores only this project, so a fresh checkout has no packages for Lumen and fails with NETSDK1004. The first call restores Lumen. Its extra property, set to a new GUID, forces MSBuild to evaluate Lumen again for the second call, so that the build sees the restored packages.
Items inside the targetA wildcard outside a target is evaluated when the project loads, before Lumen's output exists. Inside the target, it's evaluated after Lumen has been built.
LogicalName%(RecursiveDir) keeps subfolders such as de\ in the name, as payload/de\PdfSharp-wpf.resources.dll. Installer.Install turns the name back into a path.
Type="Non-Resx", WithCulture="false"Without these, MSBuild treats a file such as de\*.resources.dll as a culture-specific resource and handles it differently.

Step 8: Add it to the solution

This makes the installer build with the solution. In Visual Studio, right-click the solution and choose Add, then Existing Project. From the command line:

dotnet sln Lumen.sln add src\Lumen.DesktopSetup\Lumen.DesktopSetup.csproj

The project already builds Lumen itself, so don't add a project reference.

Step 9: Build

Close every running copy of Lumen first. An open Lumen window locks src\Lumen.Desktop\bin\Release, and the build fails.

To set the version, change <Version> in Directory.Build.props. Setup shows it in its title bar and in Windows Settings. Then build:

& $msbuild src\Lumen.DesktopSetup\Lumen.DesktopSetup.csproj -restore -p:Configuration=Release -v:m -nologo

The last line of output should read:

Lumen.DesktopSetup -> ...\src\Lumen.DesktopSetup\bin\Release\LumenSetup.exe

The exe is about 2.6 MB. Building the whole solution also produces it.

Step 10: Confirm the contents

List the embedded files, and confirm that Lumen is there and the viewer isn't. Run this in its own PowerShell session or close it afterward, because a loaded exe stays locked until the session ends:

$exe = (Resolve-Path src\Lumen.DesktopSetup\bin\Release\LumenSetup.exe).Path
$names = [Reflection.Assembly]::LoadFile($exe).GetManifestResourceNames() | Where-Object { $_ -like 'payload/*' }
$names
"Files: $($names.Count)"
"Lumen.exe: " + [bool]($names -match '^payload/Lumen\.exe$')
"Viewer files: " + @($names -match 'Viewer').Count
"Symbols: " + @($names -match '\.pdb$').Count

You should see 15 files, Lumen.exe: True, Viewer files: 0 and Symbols: 0. The file count can change if Lumen's dependencies change.

Step 11: Test it

These tests install to a temporary folder. The /noassoc switch leaves your .lumen settings alone. The Start menu link and Settings entry are real, and the uninstall test removes them.

$setup = (Resolve-Path src\Lumen.DesktopSetup\bin\Release\LumenSetup.exe).Path
$dir = "$env:TEMP\LumenInstallTest"
function Run($exe, $arguments) { (Start-Process $exe -ArgumentList $arguments -PassThru -Wait).ExitCode }

The .NET check blocks an old machine

394802 is the Release value of .NET 4.6.2. Expect exit code 2, and the second line should be False:

Run $setup @('/quiet', "`"/dir=$dir`"", '/noassoc', '/assumerelease=394802')
Test-Path $dir

The lowest allowed version installs

Expect 0, then True:

Run $setup @('/quiet', "`"/dir=$dir`"", '/noassoc', '/assumerelease=460798')
Test-Path "$dir\Lumen.exe"

The installed app works

Lumen's self-check drives the real shell and writes PNGs and a log beside the path you give it. Expect exit code 0. If the PC has been idle for 30 seconds, it also moves the real mouse for a few seconds.

$out = "$env:TEMP\LumenInstallCheck"
New-Item -ItemType Directory -Force $out | Out-Null
Run "$dir\Lumen.exe" @('--screenshot', "`"$out\out.png`"")

A running copy blocks changes

Expect 3 from both commands:

$lumen = Start-Process "$dir\Lumen.exe" -PassThru
Start-Sleep 5
Run $setup @('/quiet', "`"/dir=$dir`"", '/noassoc')
Run "$dir\uninstall.exe" @('/uninstall', '/quiet')
Stop-Process -Id $lumen.Id

Uninstall keeps your files

Add a file of your own, then uninstall. Expect 0, then my-notes.txt as the only thing left. Wait a few seconds first, because uninstall.exe deletes itself just after it exits.

Set-Content "$dir\my-notes.txt" 'keep me'
Run "$dir\uninstall.exe" @('/uninstall', '/quiet')
Start-Sleep 5
Get-ChildItem $dir | ForEach-Object Name
Test-Path "$([Environment]::GetFolderPath('Programs'))\Lumen.lnk"
Remove-Item $dir -Recurse -Force

The Test-Path line should print False, which shows that the Start menu link is gone.

The setup window

Run these and look at each window. The first should show the red message and Get .NET 4.7. The second should show Install.

Start-Process $setup -ArgumentList '/noassoc', '/assumerelease=394802'
Start-Process $setup -ArgumentList '/noassoc'

If you can, repeat this at a display scale other than 100%. A window can be correct at one scale and clipped at another.

Step 12: Distribute it

Give people LumenSetup.exe. It's the only file they need.

Command line

SwitchEffect
/quietNo window.
/dir=pathInstall folder.
/desktopAdd a desktop shortcut.
/noassocLeave .lumen files alone.
/assumerelease=nPretend .NET reports Release n. For testing.
Exit codeMeaning
0Done.

Before sharing it outside your own use

  • Code signing: the exe is unsigned, so SmartScreen warns on first run. A code signing certificate removes the "unknown publisher" warning. Sign it with signtool after the build, then again test that it runs.
  • Real older machine: the steps above simulate an old .NET. Also try the installer on a real machine.
  • No .NET 4.x at all: the check can't run on such a machine, because the installer itself needs 4.0. Windows shows its own prompt instead. Windows 10 and 11 always include .NET 4.x.
  • Third-party licenses: the install doesn't include license texts for AvalonEdit, PDFsharp, ExcelDataReader or Newtonsoft.Json. Check each package's terms and add the texts to Lumen's output, and they'll be embedded automatically.
  • Install folder: keep Lumen and Lumen Viewer in separate folders. The defaults already are. Setup doesn't stop someone from choosing the same one, and each would overwrite the other's uninstall.exe and file list.

Uninstalling leaves Lumen's autosave folder, %LOCALAPPDATA%\Lumen, on purpose. It holds the user's recovery data, not program files.

Troubleshooting

SymptomCause and fix
Build error MSB3027 or MSB3021, unable to copy Lumen.exeA Lumen window is open, or a PowerShell session loaded a file from that folder. Close it and build again.
Build error MSB3027 on LumenSetup.exe after Step 10The PowerShell session that ran LoadFile holds the exe. Close that session.
NETSDK1004, project.assets.json not foundLumen's packages weren't restored. Check that the target has the Targets="Restore" call from Step 7.
CS0246 for ProductProduct.cs isn't in the project's folder, or its namespace isn't Lumen.Setup.
Reference assemblies for .NETFramework,Version=v4.0 were not foundAdd -restore to the build so that NuGet can fetch them, or install the 4.0 targeting pack.
A UAC prompt appears when setup startsThe manifest isn't in the exe. Check that ApplicationManifest points to ..\Lumen.Setup\app.manifest.
Setup installs an old LumenLumen's output was stale or a file was left in bin\Release. Delete src\Lumen.Desktop\bin\Release and build again.
Text is cut off in the setup windowCheck that the Scale call is still the last line of the constructor, and that AutoScaleMode is None.
Double-clicking a .lumen file opens the wrong copySetup keeps an existing default. Use Open with, then Always, or change it in Settings under Default apps.
/quiet shows nothing, even on failureThat's by design. Read the exit code, as the Run function does.
