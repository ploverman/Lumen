Start here

You gave me one instruction: build a Lumen report from tranferData.csv for investors looking for trends in the housing market. Everything else was my call. This document lists those calls, grouped by topic.

Six choices shape the numbers more than all the others:

  1. Arm's-length sales only. This cuts 147,382 transfers to 70,681 and defines what a price means here.
  2. Segments. An average across all property means little, so prices are shown by segment wherever it matters.
  3. Four-month windows. With a single year of data, this is the only balanced comparison available, and it contains the season.
  4. County change minus state change. This strips out most of the season at county level.
  5. Single family as the page 3 default. Otherwise one factory sale could top a county ranking.
  6. Personal data removed. The report has no names or street addresses.

Each entry gives the choice, the reason, the main alternative and, where one exists, the trade-off. Figures come from recomputing the choice's effect on the data. IDs such as D1 are for reference if you want to ask me to change one.

What I would change

Writing the findings report tested these choices against the data, and six did not hold up as well as I expected. None makes a number in the report wrong. They affect how easily a reader could be misled.

  1. Rank counties on medians, or raise the floor. The findings report showed that averages let a few expensive sales top the ranking: Green Lake rose 44.3% on average and 5.5% on the median. Adding MEDIAN to LQL would be the right fix. Without it I would raise the floor to at least 50 sales per window, which keeps 63 counties.
  2. Add a noise warning to page 3. Only 11 of 70 county moves clear a 90% test, and chance alone would produce about 7. The page should say so in its note, since a ranked bar chart looks more certain than it is.
  3. Flag the January coding change on page 6. I saw the January spike in "Other" while building and left it unexplained. Later analysis showed conveyance codes changed around January 12, which understates January estate and foreclosure counts. The note should warn about this, or the foreclosure chart should start in February.
  4. Show both per-acre figures for land. The weighted $23,548 and the per-parcel median of $51,450 tell different stories. Without a median function, splitting land into lots and acreage at about 5 acres would be an honest substitute.
  5. Replace the page 1 donut with a sorted bar. It suited the space, but seven slices are hard to compare.
  6. Consider precomputing medians. I kept Lumen as the only calculation engine so that Refresh would stay simple. Since the median is the most important number a housing report can show, adding it to Lumen is worth doing before the next version of this report.

Purpose and overall shape

Decisions made before any data work.

S1Organize around investor questions

Choice
I built six pages, each answering one question: what is the market doing, are prices rising, where should I look, who am I competing with, what do income property and land cost, and where is the risk.
Why
Your brief named the audience as investors looking for trends. An investor reads a market in roughly that order, from the general to the specific, and ends with what can go wrong. Keeping one question per page also means each page can have a single message.
Alternative
A single dense dashboard, or one page per property type. One page cannot hold 68 visuals legibly. Pages by property type would repeat the same charts and bury the buyer and geography questions that cut across types.
Trade-off
Six pages take longer to scan. Page 1 repeats the top numbers so a reader can stop there.

S2Generate the report from code

Choice
I wrote a small C# program, ReportGen, that uses Lumen's own model classes (TableDef, MeasureDef, VisualDef) and LumenFile.Save to write the .lumen file.
Why
I cannot click through a designer the way you can. Using Lumen's classes also meant the file is valid by construction, every position is exact, and a change means rebuilding in about a minute. The build compiles every measure with Lumen's own compiler and reports failures before the file is saved.
Alternative
Writing the JSON by hand. That would skip Lumen's validation and is easy to get subtly wrong.
Trade-off
ReportGen is a scratch tool, not part of the Lumen solution. Once saved, the report is an ordinary .lumen file you can edit by hand, and the generator is no longer needed.

S3One flat table, no star schema

Choice
The model has a single table, Transfers, with no date table or dimension tables.
Why
The source is one CSV at one grain: one row per recorded transfer. Lumen filters a single table directly, and splitting County or Date into dimensions would add relationships without enabling any question this report asks. Eight months of data needs no date table because Month Index handles the window arithmetic.
Alternative
A star schema with Date, County and Property dimensions, which is the usual Power BI recommendation for larger models.
Trade-off
If you add other sources later, such as rents or 2025 data by county, a County dimension becomes worthwhile. A second year of the same file would work as is.

S4Keep the file refreshable

Choice
All cleaning lives in the report as applied steps pointing at tranferData.csv, instead of in a cleaned copy of the data.
Why
Investors will want September and later months. With the steps saved in the report, replacing the CSV and pressing Refresh rebuilds everything, and I tested that it keeps 147,382 rows and 70,681 sales. It also makes each transformation visible in the report.
Alternative
Cleaning the CSV in Python and loading the result. That would have been easier, and would have allowed medians, but it would break the link between report and source and require a separate step each month.
Trade-off
The steps are limited to what Lumen's transform engine can do, and that ruled out precomputed medians.

Data preparation

How the raw file became the model, in step order.

P1Treat a blank price as a malformed row

Choice
I convert Sale Price to a number first, then filter out rows where it is blank.
Why
Stray quotes in legal descriptions split about five transfers into 10 broken rows. Those rows are the ones with blank prices once the column converts, and every valid row in the file has a value there. Non-sale transfers carry a price of 0 or a real number, so the filter removes nothing else. This took the file from 147,392 parsed rows to 147,382.
Alternative
Repairing the broken rows. The effort is large for five records, and a repair would need custom parsing that a Lumen Refresh could not repeat.
Trade-off
Those five transfers are lost. I accepted that because they cannot move any statewide figure.

P2Use Recorded Date as the time axis

Choice
Every month, window and trend uses Recorded Date, not Conveyance Date.
Why
The file is assembled by recording month (202601 to 202608), so recorded date gives complete, evenly defined months. Conveyance dates are entered on the return, and 9,057 of them fall before 2026, with the earliest in 1969. Using them would scatter records across years the file does not cover.
Alternative
Conveyance Date, which is closer to when the deal happened.
Trade-off
A sale that closed in late March may count in April. This shifts the timing slightly and leaves the latest month open to late filings.

P3Rename columns into reader language

Choice
Grantor became Seller, Grantee became Buyer, and long names were shortened, such as Primary Residence of Grantee? to Primary Residence and Property Use Sub Type to Commercial Use.
Why
Investors think in buyers and sellers, and these names appear in tooltips, tables and the field list. A column name that needs translating slows every reader. The question marks would also have needed awkward quoting in measures.
Alternative
Keeping the RETR names so the report matches the form exactly.
Trade-off
Anyone comparing with the state's documentation has to map the names back. The applied steps record each rename.

P4Fix inconsistent casing

Choice
Five values in Commercial Use were changed to sentence case, such as Contractor Shop to Contractor shop.
Why
The rest of the column uses sentence case and the mixed values looked like errors in the commercial table on page 5. Each fix is a saved step, so it survives a refresh.
Alternative
Leaving the source values untouched.

P5Keep 29 columns and drop personal data

Choice
I kept only columns the report uses and removed names, street addresses and legal descriptions. The final step removes them after the derived columns are computed.
Why
Two reasons. Names and addresses of private buyers have no place in an investor report, and a report file gets shared. Removing wide text columns also cut a 192 MB CSV to a 3.4 MB report, because columnar compression does poorly on unique text.
Alternative
Keeping everything so readers could explore freely.
Trade-off
You cannot look up an individual property from the report. Document Number stays, so any record can still be traced back to the CSV.

P6Keep Municipality

Choice
Municipality stays in the model, even though it appears in only one visual.
Why
Investors buy in towns, not counties, and county averages hide large differences. The drill-down on page 3 lets a reader go from Dane County to a specific municipality.
Alternative
Dropping it to keep the model smaller.

P7Derive Buyer State from the mailing address

Choice
I read the two letters before the ZIP code in the buyer's address, handling both 5-digit and ZIP+4, and accept them only if they match a list of 51 state codes. Anything else becomes Unknown.
Why
The file has no buyer-state field, and out-of-state money is a central investor question. Checking against a fixed list keeps parsing errors from creating false states. The pattern fails on 2,304 of 70,681 sales, and those are left out of the share so they cannot look like Wisconsin buyers.
Alternative
A broader address parser, which LQL's string functions cannot express well.
Trade-off
A mailing address is a proxy. A buyer who has already moved here, or who uses a Wisconsin agent's address, counts as Wisconsin.

P8Clean the acres column

Choice
Clean Acres keeps values above 0 and up to 10,000 and blanks the rest.
Why
Zero or blank acres means the field was not filled in (14,228 sales). The 11 sales above 10,000 acres are entry errors, such as a single-family home at 142,877 acres and two farm records at 2,257,279 acres, which would swamp any total. I set the limit well above any believable Wisconsin sale.
Alternative
A statistical outlier rule. A fixed limit is simpler to explain and stable across refreshes.
Trade-off
The 10,000 limit is a judgment call. No Land sale exceeds it, so land figures are unaffected. Only the 11 other records are.

P9Store Month as a date and a hidden integer

Choice
Month is the first day of the month, formatted MMM yy. Month Index is year * 12 + month and is hidden.
Why
The date keeps charts in calendar order without a sort column. The integer lets a measure subtract 4 or 8 months with plain arithmetic, and it stays correct across a year boundary when 2027 data arrives. Hiding it keeps the field list clean.
Alternative
Time-intelligence functions such as DATEADD, which need a proper date table.

P10Add Quarter though no visual uses it

Choice
A Quarter column exists in the model, and the window measures clear it alongside Month.
Why
I expected readers to add a quarter slicer or matrix. Clearing it in the window measures means that such a filter will not silently break them.
Alternative
Leaving it out. Either would be fine today, since Q3 has only two months.
Trade-off
One unused column for now.

P11Sort price bands with a hidden column

Choice
Band Order holds 1 to 5, and Price Band sorts by it.
Why
Text sorts alphabetically, which would put $1M+ first and Under $150K last. A sort-by column is the same pattern you would use in Power BI.
Alternative
Prefixing labels with numbers, which is uglier.

Business definitions

These have the largest effect on the numbers. Each one decides what counts.

D1Define an arm's-length sale with seven conditions

Choice
Prices and shares use only sales passing all seven conditions below.
Why
The file records every deed, including gifts, trusts, divorces and corrections. Fewer than half of the transfers are market sales. An investor wants to know what a willing buyer paid a willing seller, so anything that could carry a non-market price is out. The largest cut by far is the first one. After that, the conditions remove about 8,000 rows between them.
IF([Conveyance Type] = "Sale"
   && [Party Relationship] = "No relationship"
   && [Part of Parcel Transferred] = "1. Entire parcel"
   && [Ownership Type] = "Full"
   && [Sale Price] >= 10000
   && LEFT([Document Type], 4) <> "WDOT"
   && [Property Type] <> "Timeshare", "Yes", "No")

Alternative
Using every row with a price. A parent selling to a child for $1, or a partial interest, would pull averages toward prices nobody could actually buy at.
Trade-off
A few genuine market sales are removed, such as a real sale between relatives. I preferred a cleaner sample over a larger one.

D2Set a $10,000 price floor

Choice
Sales under $10,000 are excluded, even between unrelated parties.
Why
Very low prices on a recorded sale usually mean a nominal consideration, a fractional deal or a transfer that was not really a sale. I chose a round number low enough to keep real cheap land. I tested the choice afterward: statewide levels move slightly, and the single-family trend barely moves at all.

No floor, or a higher one such as $25,000.

A few real low-price rural lots are dropped. The sensitivity table shows that the trends do not depend on this number.

D3Require the entire parcel and full ownership

Choice
Sales of part of a parcel, a partial interest or improvements only are excluded.
Why
A half interest sells for roughly half, and that price says nothing about what the property is worth. Including these would mix fractional prices with whole-property prices. This removes 3,040 rows for part of a parcel and 141 for ownership.
Alternative
Scaling the price up by the fraction sold. The form does not give a reliable fraction, and minority interests often sell at a discount anyway.

D4Exclude WDOT documents

Choice
Documents starting with WDOT are out.
Why
These are state road-related transfers. Government takings are priced by negotiation or condemnation, not by a market, and they are not a transaction an investor could join. Only 94 sales were affected, so this is a matter of definition more than effect.
Alternative
Leaving them in, which would change nothing visible.

D5Separate timeshares from everything else

Choice
Timeshare is the first test in both Segment and Transfer Channel, and timeshares are excluded from sales and foreclosures.
Why
A timeshare is a week of use at a resort, so its price cannot sit beside a house. There are 974 such rows. They mattered more than I expected: 74 of them were coded as foreclosures, 61 in Walworth County and 13 in Sauk, and they made Walworth look like a distress hot spot. I added the Timeshare channel after spotting that.
Alternative
Treating them as condos or leaving them under Other.

D6Assign segments by first match in a fixed order

Choice
Segment is a nested IF, and order matters. Each row gets exactly one segment.
Why
The source has two overlapping fields, Property Type and Property Use Type, so a single-field mapping would not work. Testing Property Type first catches condos, which are coded with a residential use class but behave as their own market. Land comes after Commercial and Farm so that a farm parcel recorded as land only stays classed by its use.
IF Property Type = Timeshare                 -> Timeshare
IF Property Type = Condominium               -> Condo
IF Use = Multi-family                        -> Multi-family
IF Use IN Class 2, Class 3, Utility, Telephone -> Commercial
IF Use IN Class 4, Class 5m, Class 6         -> Farm & forest
IF Property Type = Land only OR Use = Class 5 -> Land
IF Use = Single family (Class 1)             -> Single family
ELSE                                         -> Other
Alternative
Using Property Use Type alone, which mixes condos into single family.
Trade-off
Other holds 710 sales, mostly Class 7 "other" property. That is small enough to leave undivided.

D7Group commercial and farm classes

Choice
Commercial combines Class 2, manufacturing, utility and telephone. Farm & forest combines Class 4, 5m and 6.
Why
Wisconsin's assessment classes are too fine for a trend chart, with some having very few sales. These groups match how an investor would think about the asset, and the detail survives in the commercial-use table on page 5.
Alternative
Showing each class separately, which would have produced many thin, noisy lines.

D8Five buyer classes, with trusts on their own

Choice
Individual, Trust, LLC / partnership, Corporation, and Government & other. Entity Buyer Share counts only LLC / partnership and Corporation. REITs and financial institutions sit under Corporation.
Why
The aim of entity share is to estimate business and investor buying. Revocable trusts are usually how a family holds its home, so counting them as investors would overstate the signal. Five groups keep the stacked chart readable.
Alternative
Counting trusts as entities. That raises the share from 17.4% to 21.9%. The falling trend remains, from 27.2% in January to 20.6% in August, so the conclusion holds either way.
Trade-off
Some trusts are real investors, and some LLCs are a single family holding a cabin. Entity type is an imperfect stand-in for investor intent.

D9Seller classes for distress and supply

Choice
Seller Class has three values: Bank / agency, Estate, and Other.
Why
Page 6 only needs two seller signals. A bank or federal agency selling suggests a resale after foreclosure, and an estate selling is a supply signal. A full seller breakdown would add nothing for those questions.
Alternative
A seller classification mirroring Buyer Class.

D10Price bands at $150K, $300K, $500K and $1M

Choice
Five bands with round thresholds.
Why
Lumen has no median, so the band mix has to show where the middle of the market is. Bands placed around the single-family median of about $327,000 show movement through the middle, and the outer bands catch the entry level (about 12% of sales) and the luxury end (about 3%). Round numbers match how buyers set a search.
Alternative
Equal-width bands or quantile bands. Equal width would crowd most sales into two bands. Quantile bands would change with each refresh, so a trend in them would mean nothing.

D11Building sizes of 2-4, 5-19 and 20+ units

Choice
Multi-family is split into these three groups.
Why
The 2-4 boundary follows US residential lending: up to four units can use a residential mortgage, and five or more is a commercial loan. That is a real change in who can buy. The 20+ group separates institutional deals.
Alternative
Average units per sale, which hides the shape of the market.

D12Classify every transfer into channels

Choice
Transfer Channel gives each of the 147,382 rows one label: Timeshare, Arm's-length sale, Other sale, Foreclosure, Estate & inheritance, Family & trust, Entity restructuring, or Other.
Why
Page 6 is partly about what is not a market sale. A single column makes foreclosures and estates easy to count and shows on one chart what the arm's-length filter discards. That transparency lets a reader judge the filter.
Alternative
Separate true/false flags, which allow overlaps and need several columns.

D13Count foreclosures among all transfers

Choice
Foreclosures counts foreclosure and judgment transfers whether or not a price or arm's-length test applies. The per-1,000 figure divides that by arm's-length sales.
Why
A sheriff's deed is not an arm's-length sale by definition, so filtering to sales would hide nearly all of them. Dividing by sales scales the count to each county's market size so Milwaukee and Rusk can be compared.
Alternative
Dividing by housing stock, which would be the proper foreclosure rate. The file has no housing count.
Trade-off
The two sides of the ratio are different populations. It works for comparing counties, but it is not the share of homes foreclosed.

D14Treat estate transfers as a supply signal

Choice
Estate Transfers combines termination of decedent's interest, will or survivorship, PR-1831 affidavits and trustee to beneficiary.
Why
Some homes pass to heirs who then sell. That gives an investor an early look at supply before a listing appears, in counties where this runs high.
Alternative
Leaving them out as non-sales.
Trade-off
Many of these will be a surviving spouse or a trust distribution that never reaches the market, so it is a lead indicator at best. The page note says so.

Measures

How the numbers are calculated.

M1Build the sale filter into the base measures

Choice
Sales and Dollar Volume carry the arm's-length condition, and other measures build on those two.
Why
Page 6 needs all transfers, so a report-level filter would not work. Putting the rule in two base measures means it lives in one place, like a single private method that the rest of a class calls. A reader cannot accidentally get an unfiltered average.
Alternative
A report-wide filter, or repeating the condition in each measure.

M2Compare the latest four months with the prior four

Choice
Change measures compare the latest 4 months with the 4 before, found from the highest Month Index in the data.
Why
A year-over-year comparison is impossible with one year. Month-over-month is noisy, especially in small counties. Quarters do not fit, because Q3 has only two months. Eight months split evenly into two windows, which gives each county the largest possible sample. The windows are computed from the data, so they roll forward after a refresh without any edits.
VAR m = CALCULATE(MAX(Transfers[Month Index]), ALL(Transfers))
RETURN CALCULATE([Avg Price], ALL(Transfers[Month]), ALL(Transfers[Quarter]),
                 Transfers[Month Index] > m - 4)
Alternative
Year over year, month over month, or quarter over quarter.
Trade-off
The two windows are January to April and May to August, so every statewide change includes the seasonal lift. I labelled this on the page and handled it for counties with the next choice.

M3Rank counties against the state

Choice
County momentum is the county's 4-month change minus the state's, in percentage points.
Why
Nearly every county rises from winter to summer, so raw change would mostly rank the season. Subtracting the state removes the shared lift and leaves what is specific to the county. It is the best available substitute for year-over-year data.
Alternative
Ranking raw change.
Trade-off
It assumes all counties have the same seasonal pattern, and vacation counties probably do not.

M4Require 30 sales in each windowWould revisit

Choice
Price vs WI and Volume vs WI return BLANK when either window has fewer than 30 sales.
Why
An average of a dozen sales says little, and the smallest counties would otherwise fill the top and bottom of every ranking. Thirty is the usual rule of thumb for an average to settle down. It keeps 70 of 72 counties. Returning BLANK also makes those counties disappear from TopN visuals.
Alternative
A higher floor. At 50 sales 63 counties remain, and at 100 sales 48 remain.
Trade-off
Thirty proved too low for averages. See the first item in "What I would change".

M5Benchmark within the selected segment

Choice
The state benchmark clears only County and Municipality, using ALL(), and leaves Segment alone.
Why
If a reader selects Condo on page 3, each county should be compared with the state's condo market. A benchmark that cleared every filter would compare county condos with all Wisconsin property.
Alternative
A fixed all-property benchmark.

M6Clear only time filters in the windows

Choice
The window measures clear Month and Quarter, and respect County and Segment.
Why
Clicking a month bar cross-filters the page. Without clearing time, the 4-month card would be asked for a window inside a single month and return nonsense. The card intentionally ignores a month click and responds to geography and segment.
Alternative
Letting time filters through.
Trade-off
The cards do not change on a month click, which could surprise someone. The behavior is correct, since the card describes fixed windows.

M7Choose each share's denominator on purpose

Choice
Non-Owner Share divides by sales that answered the question. Out-of-State Share divides by sales with a known state. No-Financing Share divides by all sales.
Why
A share is misleading if unknowns are treated as "no". The primary residence question is blank on 13% to 19% of sales, and those blanks are not a statement either way. Financing is filled on every arm's-length sale, so all sales is correct there. I verified that when writing the findings report.
Alternative
Dividing everything by all sales, which is simpler and would understate two of the four shares.

M8Call it no financing, not cash

Choice
The measure and labels say No-Financing, and the page note calls it a proxy for cash.
Why
The form records whether financing was reported, not how the buyer paid. Calling it cash would claim more than the data knows.
Alternative
The shorter "Cash Share", which is what most readers will mentally call it anyway.

M9Compute ratios of totalsWould revisit

Choice
Price per Door is total dollars over total units. Price per Acre is total dollars over total acres.
Why
This is the weighted figure a portfolio buyer uses: what the market paid per unit overall. An average of per-sale ratios would let a tiny parcel with an extreme per-acre price count as much as a 500-acre farm. Multi-family sales with no unit count (68) are excluded from door pricing.
Alternative
Average of each sale's ratio. A median would be better still, but Lumen has none.
Trade-off
Weighting has a cost for land: the $23,548 per acre is driven by large rural tracts, while the median parcel sold at $51,450 an acre.

M10Require 100 sales for the out-of-state county chart

Choice
Out-of-State Share (100+ sales) returns BLANK for counties below 100 sales.
Why
This is a higher floor than momentum because the chart ranks a share of a county, and at low counts a few buyers can produce 50%. At 100 the list is credible and still shows the northern lake counties.
Alternative
Using the 30-sale floor.

M11Show the data date on page 1

Choice
Data Through shows the latest recorded date, Aug 31, 2026.
Why
A trend report needs to say how current it is, and this updates by itself after a refresh.
Alternative
Typing the date in a title, which goes stale.

Pages and visuals

What readers actually see, and why it looks that way.

V1Put a definition note at the top of each page

Choice
Each page opens with a one-line note about what the numbers mean.
Why
Readers often skip documentation, and a page shown without its definitions gets misread. The note appears exactly where the question arises, for example that foreclosures include non-sales.
Alternative
A help page, which few readers would open.

V2Keep a consistent right rail

Choice
A 212-pixel column on the right of each page holds the slicers and context cards, at the same position.
Why
A reader who learns where the filter is on page 1 finds it there on every page. It also gives the main chart area a stable width on a 1280 by 720 canvas.
Alternative
Placing slicers next to whichever chart they matter most for.

V3Use a dropdown for County, a list for Segment

Choice
County is a dropdown slicer. Segment is a list slicer on the pages that have one.
Why
With 72 counties, a list would take the whole rail. Eight segments fit in a list, where seeing them all helps the reader understand what is available.
Alternative
One style throughout.

V4Default page 3 to Single family

Choice
The Segment slicer on page 3 starts with Single family selected.
Why
County averages across all property are mostly a measure of which counties had large commercial sales. A $50M factory sale would top the momentum ranking. Starting with one homogeneous segment gives a meaningful ranking right away, and readers can change it.
Alternative
No default selection, which would be misleading on first view.
Trade-off
A reader who misses the slicer may assume the page covers all property. The slicer is prominent for that reason.

V5Use averages, and show bands to fill the gapWould revisit

Choice
Prices are averages, and page 2 pairs them with a price-band mix.
Why
This was forced. LQL has no MEDIAN or PERCENTILE. The stacked band chart is the closest available view of the middle of the market, since it shows whether the distribution moved or only the top did. Page 2's note states the limitation.
Alternative
Precomputing medians outside Lumen, which would break Refresh. See "What I would change" for what I now think about this.
Trade-off
Averages are sensitive to single large sales. The findings report added medians separately.

V6Remove multi-family from the trend lines

Choice
The two page 2 line charts show Single family, Condo and Land. Multi-family stays in the matrix below.
Why
I included it first. Its average jumped between $468,000 and $942,000 as single large deals landed, which flattened the other lines and looked like news when it was only deal mix. It has its own measure on page 5, price per door.
Alternative
Keeping it in, or giving it a second axis, which would make two scales look comparable when they are not.

V7Show price both as dollars and as change

Choice
Page 2 has one line chart of average price and another of percent change since January.
Why
Dollar lines show level, but segments at $190,000 and $380,000 cannot be compared by slope. Rebasing every line to its first month puts them on one scale, so the rates of change can be compared.
Alternative
Only one of the two.
Trade-off
The rebased chart depends on January being a typical base month.

V8A scatter of price against momentum

Choice
Page 3 opens with a scatter: average price across, price vs WI up, bubble size for sales, limited to the top 35 counties by sales.
Why
An investor's question is whether a market is cheap and improving. That takes two variables at once, and a scatter shows it in one view. Limiting to 35 counties keeps out the thin markets and stops the labels from colliding.
Alternative
A table, which requires the reader to compare two columns mentally.

V9Pair strongest and weakest county barsWould revisit

Choice
Two bars rank the top and bottom 10 counties by Price vs WI, using TopN visual filters.
Why
Weakness matters to an investor as much as strength, either as a warning or as value. Seeing the two lists together also shows the scale of the spread, and how much of it is likely noise.
Alternative
A single sorted chart of 70 bars, which would not fit.
Trade-off
Rankings imply precision. The findings report tested this and found that few of these moves clear a noise test.

V10Add a county table and municipality drill

Choice
Below the charts, one table holds all counties with sortable columns, and a matrix expands County into Municipality.
Why
Charts show the top and bottom, but an investor often has a specific county in mind. The table covers all counties and lets a reader sort by any signal. Lumen has no preset table sort, so the title tells the reader to click a header.
Alternative
Only the chart views.

V11Put four investor signals on one line chart

Choice
Non-owner, no-financing, entity and out-of-state shares are on one chart.
Why
All four are percentages of sales, so one axis is honest and comparison across them is the purpose. This chart also shows that they do not all move together, which is the key message of page 4.
Alternative
Four small charts, which would take space and make comparison harder.

V12Show out-of-state buyers from two angles

Choice
One chart shows which states they come from, and the other shows which counties rely on them.
Why
These are different investor questions: where is the demand coming from, and which local markets depend on it. Using both revealed the pattern of Illinois buyers along the southern border and Minnesota buyers along the northwest.
Alternative
A single table by state and county.

V13Show all transfers on page 6

Choice
The transfer channel chart stacks every recorded transfer by month, including non-sales.
Why
This is the only place in the report showing what the arm's-length filter removes, so a skeptical reader can see the whole file. It is also how the January "Other" spike became visible.
Alternative
Showing only sales, as the other pages do.

V14Rank counties by commercial volume on page 5

Choice
The income-property table shows the top 25 counties, ranked by commercial volume, with multi-family and land columns alongside.
Why
Income property is thin in most counties, so a full list would be mostly empty rows. Commercial volume is the best single indicator of whether a county has an institutional market.
Alternative
All 72 counties, or ranking by multi-family sales.
Trade-off
A county strong in multi-family but weak in commercial could rank lower than it deserves. The County slicer still reaches it.

V15Leave out a table of largest deals

Choice
No visual lists individual transactions.
Why
A top-deals list is interesting, but it identifies specific properties and parties. The personal columns are gone from the model, and a top-deals table would have worked against that. The findings report names the largest deals only by place and price.
Alternative
A top-20 deals table, which many investors would enjoy.
Trade-off
Readers who want deal-level detail have to go to the CSV.

V16Use one color for single-series charts

Choice
Charts with one measure all use the same blue. Color appears only when a chart has a legend.
Why
Color should carry information. If each single-series chart had its own color, readers would look for a meaning that does not exist. This also saves palette entries, see the next section.
Alternative
Lumen's default of automatic colors.

Working around Lumen's limits

Lumen is young, and I hit some limits. These are choices forced by the tool, and you may want to fix them in Lumen itself.

L1Plot percent-point versions of shares

Choice
Nine measures in a Chart folder multiply a share by 100, with a format like 0.0'%'.
Why
Chart axes in Lumen ignore format strings, so a share of 0.17 would appear as 0.17 on the axis. Multiplying by 100 makes the axis read 17. Tables and cards keep the proper decimal measure.
Alternative
Plotting raw decimals, or changing Lumen.
Trade-off
Each share has two measures, which clutters the field list. The folder contains that clutter.

L2Use a text measure as a text box

Choice
Page notes are text measures in a Notes folder, displayed in borderless cards.
Why
Lumen has no text box visual. A card displays any measure's value, so a measure returning a string works as a label.
Alternative
Leaving notes out, or putting them in titles, which are too short.

L3Use a 36-color theme

Choice
The report has a custom theme with 36 distinct colors.
Why
Lumen gives each series name a color on a first-come basis across the whole session, and its default palette wraps. By page 4, different series were getting the same color. A long palette keeps each name distinct.
Alternative
The default theme.
Trade-off
Later colors are less harmonious, and many of the 36 are never seen.

L4Reduce line chart axis text to 9 points

Choice
All line charts use AxisFontSize 9.
Why
Lumen draws the last X label past the plot edge, and at the default size "Aug 26" was clipped. Smaller text fits.
Alternative
Fixing the renderer in Lumen, which was outside this task.

L5Place scaling commas before the decimal

Choice
Dollar volume uses $#,0,,.0'M'.
Why
.NET only scales by a comma directly left of the decimal point. My first attempt, $#,0.0,,'M', displayed unscaled numbers.
Alternative
Dividing by a million in the measure, which breaks totals and tooltips.

L6Accept zero-based line charts

Choice
Price lines start at $0.
Why
Lumen forces a zero baseline on line charts. Monthly changes of a few percent therefore look flat on page 1. The rebased chart on page 2 was partly added to make up for this.
Alternative
None available without changing Lumen.
Trade-off
The price trend looks weaker than it is on page 1.

L7Turn off the axis on stacked percent charts

Choice
The band chart hides its Y axis and gridlines.
Why
Every column totals 100, so the axis adds nothing, and removing it gives the legend and bars more room.
Alternative
Leaving the axis on.

How I checked it

The checks were choices too, since they cost time and decide what can be trusted.

V1Recompute everything independently

Choice
I recalculated the key figures in Python from the CSV with separately written logic, and compared them with Lumen's.
Why
A bug in my definitions or in Lumen's engine would produce plausible, wrong numbers. Two separate implementations agreeing makes both errors unlikely. They matched exactly, including 70,681 sales and the $417,234 average.
Alternative
Reading the charts and judging whether they looked right.

V2Open the report in the real Lumen window

Choice
A driver opened the file through Lumen's normal startup path, drew each page, logged every visual's results and saved a screenshot.
Why
A file that saves is not proof that it renders. This caught clipped columns, color collisions and the axis label problem, none of which a data check would find. All 68 visuals rendered with no errors.
Alternative
Trusting that a valid file renders properly.

V3Test the interactions

Choice
I set the County slicer to Dane, cross-filtered by clicking June, cleared it, then ran a real Refresh from the CSV.
Why
Slicers, cross-filtering and refresh are where measure logic most often breaks. Each result matched the expected value: Dane gave $566,135 and 6,009 sales, June gave $401,485 and 11,587 sales, and Refresh kept every count.
Alternative
Testing only the default view.
