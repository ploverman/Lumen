Lumen Developer Manual

Architecture, data flow and extension points of Lumen, for an experienced C# developer picking up the code. It assumes you know WPF and async, and have used Power BI or another tabular BI tool.

1. Orientation

Lumen is a Power BI Desktop-style report builder: WPF on .NET Framework 4.7, x64, C# 7.3, no JavaScript and no browser control. It is about 12,800 lines of C# in six projects, plus a test project. The specification is PRD-dashboard-builder-wpf-net47-no-js.md, and this code is its Phase 1 MVP (section 5.1). Phases 3 and 4, which cover the server, were not built.

Four design decisions explain most of the code:

  1. Everything is columnar and dictionary-encoded. Filters become bitsets over rows, and aggregations run over typed arrays. Allocation per row is avoided on every query path.
  2. The document is JSON-serializable data. ReportDocument holds no behavior or row data, so undo is a JSON snapshot, and save is that JSON plus column files.
  3. Charts are retained-mode DrawingVisuals, not element trees. A chart is one FrameworkElement. Hit testing goes through a plain list of marks.
  4. Visuals don't touch the engine. A visual declares queries and receives results. All data access runs in one batch that the canvas owns.

Language rule: C# 7.3 only. No switch expressions, using var, ??=, records, nullable references or target-typed new. There is no XAML apart from App.xaml (theme-aware styles); views are built in code using the helpers in Ui.

4. A slicer click, end to end

This path crosses every layer. Read the code in this order and the rest falls into place.

  1. Publish. The slicer builds a FilterDef and calls IVisualHost.SetSlicerFilter. The canvas stores it as SlicerState on the VisualDef. That is saved in the file, but it is not an undo step and doesn't mark the document dirty.
  2. Coalesce. ReportCanvas.Refresh(delay) cancels the current CancellationTokenSource and waits 30 ms, so rapid clicks collapse into one run.
  3. Build. For each visible visual, BuildQueries produces specs and ComposeFilters merges report, page, visual and slicer filters plus any cross-filter selection. A slicer skips its own filter. With Highlight mode, selection filters go in QuerySpec.Highlight.
  4. Execute. The batch runs off the UI thread. Each spec checks the result cache, keyed by dataset version and spec JSON with filter ids stripped.
  5. Mask. Each filter resolves to a row Bitset on the table it needs, memoized per filter in the dataset, so visuals in one refresh share work.
  6. Partition. Rows that pass the mask are partitioned by group key once per query.
  7. Evaluate. Compiled measures run per group over those partitions, in parallel across groups or row chunks.
  8. Draw. Back on the UI thread, each container stores its results and calls Update. The Performance pane gets its text from the same pass.

5. Lumen.Model

Value

Value is a readonly struct holding a kind, an integer payload (also date ticks and booleans), a double and a string. Boxing is avoided, but the struct is large, so hot paths use typed arrays and meet Value only at the edges. Value.Compare defines the sort order, with BLANK first.

Query contract

QuerySpec is the equivalent of one visual's SUMMARIZECOLUMNS: GroupBy, Measures, Filters, Highlight, OrderBy, TopN, Limit (default 3,500) and IncludeTotals. QueryResult is columnar, indexed Data[column][row], group columns first. RowKey(row) joins the group labels with U+001F, which is how selections and highlights align across queries.

6. Engine: column store

Columns.cs holds the storage types.

TypeStorage
DoubleColumndouble[] and a null bitmap. Also used for Decimal, which trades decimal exactness for tight loops.
Int64Columnlong[] and a null bitmap.
DateColumnTicks in a long[].
DictColumnint codes into a dictionary. Strings and booleans.

Column.Encoded lazily builds an Encoding for any column: a sorted dictionary, a code per row, and a representative row per code. Code 0 is always BLANK. This makes grouping, distinct counts and predicate evaluation uniform over all types. Predicates run once per dictionary entry, then filters test a lookup table per row.

Bitset is the filter representation: one bit per row, with word-at-a-time AND/OR and popcount.

Par is the parallel primitive. Par.Ranges and Par.Sum use fixed chunks of 65,536 rows. Two properties depend on that fixed size. It is a multiple of 64, so chunks never share a bitset word, and writes need no synchronization. And floating-point sums are deterministic, because the same chunks combine in the same order regardless of thread count.

Dataset is immutable once built: tables, resolved relationships, compiled measures and memo tables. Any model or data change makes a new one, which is the cache-invalidation story. fkToDimRow maps a fact row to its dimension row for each relationship. Orphan keys map to no row, and group as BLANK. A lazily built inverted FkIndex in CSR form maps a dimension row back to its fact rows.

7. Engine: filters

FilterContext is an immutable set of column filters. Applying one to a table walks the relationships from one side to many side. Direction is single only: a filter on a fact table doesn't reach a dimension.

  1. Same table. Evaluate the predicate per dictionary code, then scan the codes into a mask.
  2. Across a relationship, wide filter. Compute the dimension's row mask, then scan the fact table's fkToDimRow in parallel.
  3. Across a relationship, narrow filter. When selected dimension rows times 8 is less than the dimension's length, and the fact table is larger than Par.Chunk * 2, use the inverted index and set bits directly. A single-month filter on a date table touches a small part of the fact table this way.

Memoization. Masks live in Dataset.MaskMemo and RowMemo as Lazy values, keyed by "c:" + cf.Sig or "r:" + rel.Id + "=" + hash, combined with the signature and table. NoteMemo caps them at 256 MB. Per-group contexts reuse masks, so a 40-bar chart doesn't rescan 40 times. A cancelled Lazy would cache its exception, so QueryScope.Shared<T> detects that and evicts it.

TopN filters apply last, through a nested query: rank the column by the measure, then filter to the winners.

8. Engine: query execution

QueryScope lives for one query. It holds the partitions, the pooled buffers and the cancellation token.

  1. Driver. PickDriver chooses the table to iterate. With measures it's the largest table that reaches all group tables. Without measures, as for a slicer, it's the smallest.
  2. Group keys. Each group column contributes its dictionary codes to a mixed-radix integer key.
  3. Partition. If the key space is at most 1 << 20 a dense array counts rows per key. Otherwise a sparse map is used. Key buffers are pooled, with at most 4 held.
  4. Measures. Each table a measure touches gets a Lazy<Partition>, and its ProjectionMask records which group columns that table sees. Aggregates reuse the partition instead of rescanning.
  5. Parallelism. With at least 4 groups and a driver over Par.Chunk * 2, groups evaluate in parallel. Otherwise each aggregate can parallelize over chunks.
  6. Post-processing. Groups whose measures are all BLANK are dropped. Sort honors OrderBy, then group display order, using sort-by columns. Then TopN and Limit.
  7. Totals and highlight. Totals evaluate separately, so ratios are right. Highlight is a second QueryScope aligned by RowKey.

Result cache. InProcessEngine keeps results keyed by dataset version plus the spec's JSON, with filter Id values removed by regex, because each slicer click creates a new FilterDef id. Up to 4,000 entries. A hit returns the same QueryResult instance, so treat results as immutable.

9. LQL: parser and compiler

Parser

LqlParser.cs is a hand-written lexer and Pratt parser. Binding powers: || 1, && 2, comparisons and IN 3, & 4, + - 5, * / 6, ^ 7 right-associative, unary 8. Unary above ^ differs from DAX, so -2^2 is 4. Errors carry position as LqlDiagnostic (line, column, offset, length), which the editor's squiggle uses.

Compiler

LqlCompiler compiles the AST to a closure tree, not IL:

public delegate Value Eval(EvalCtx c);          // scalar expression
internal delegate double RowFn(int row);        // row kernel, no Value
internal delegate int[] TableEval(EvalCtx c);   // table expression
internal delegate FilterContext Modifier(EvalCtx outer, FilterContext f);  // CALCULATE argument
  • EvalCtx carries the filter context, the row context and variables.
  • Scope is the compile-time binder for variables and row-context tables.
  • Measures compile once per Dataset. A [ThreadStatic] in-flight set detects self-reference.
  • RowFn kernels: SUMX over + - * of numeric columns compiles to a typed row function, which runs in parallel with no Value churn. Anything else falls back to row-by-row Eval.
  • CompiledTable records TableId, ColumnId, Rows and Modify, so that one compiled table expression can act as iterator input or as a CALCULATE filter.
  • CALCULATE boolean predicates must use exactly one column, and are evaluated once per dictionary code, then cached.
  • RELATED goes through fkToDimRow. Time intelligence requires a table with DateTableColumnId set.

Semantic differences that matter

  • No context transition. CALCULATE or a measure inside an iterator doesn't convert the row context into filters. This is the largest gap from DAX.
  • / follows IEEE doubles (Infinity, NaN). DIVIDE returns BLANK or the alternate.
  • BLANK behaves as zero in + and -, as in DAX.
  • COUNT and COUNTA are the same aggregate here. VALUES is DISTINCT.
  • MIN and MAX also accept two scalar arguments.
  • FORMAT takes .NET format strings.
  • DATESYTD and SAMEPERIODLASTYEAR replace all filters on the date table.

10. Connectors and transforms

ColumnBatch is the interchange type: columns with names and types, not yet bound to model ids. The pipeline is ReadSource to ApplySteps to Bind:

{
    switch (src.Kind) {

        case "json":   return JsonConnector.Read(src.Path, ct);
        case "sql":    return SqlConnector.Read(src.ConnectionString, src.Query, ct);
        case "sample": return SampleData.Batch(src.Query, 50000);
        ...
  • Type inference tries Int64, Double, Boolean, Date (length 8 or more), then String.
  • CSV is hand-written; the delimiter comes from the first line.
  • SQL. Text starting with select or with passes through; anything else is treated as a table name and goes through QuoteName. CommandTimeout is 300 seconds. DatabasesAsync serves the dialog's database list.
  • Transforms. TransformStepDef is data (Kind, Label, string Args), and TransformEngine.Apply switches on Kind. Each step takes and returns a ColumnBatch.
  • AddCustomColumn compiles an LQL expression against a throwaway dataset of the batch.
  • DetectRelationships requires the same name and type, one side all-distinct with no blanks, and the many side at least as long.

11. Charting and visuals

Contract

public interface ILumenVisual : IDisposable
{
    VisualCapabilities Capabilities { get; }
    FrameworkElement CreateView(IVisualHost host);
    IReadOnlyList<QuerySpec> BuildQueries(VisualDef def, SemanticModel model);  // UI thread, no data access
    void Update(VisualUpdate update);                                           // UI thread
}

IVisualHost is the only way out of a visual: Select, ClearSelection, ShowTooltip, HideTooltip, ColorFor, SetSlicerFilter. Returning no queries from BuildQueries means the wells are incomplete.

Drawing

ChartHost is a FrameworkElement holding four DrawingVisual layers: GridLayer, MarksLayer, AxesLayer, OverlayLayer. Brushes and pens are frozen (Frozen.Brush, Frozen.Pen), and geometry is frozen StreamGeometry from ShapeBuilders. Frozen objects are cheaper to render, and safe to share.

ChartVisual is the base class. It handles empty and error states, routes the mouse through Marks, and calls your Render(). A Mark is a plain object: a Rect or Geometry for hit testing, a DataPoint and tooltip lines. Hit testing walks the list backward, since later marks paint on top.

Cross-cutting behavior

  • Highlight. When Capabilities.SupportsHighlight is false, the canvas sends the selection as a filter.
  • Colors. Session.ColorFor assigns theme colors by first seen, so a name keeps its color across a page.
  • Format. A format class is a POCO with [FormatCard] and [FormatProperty] attributes. VisualizationsPane.BuildFormat generates its editors by reflection. VisualDef.Format stores overrides only, and VisualRegistry.ReadFormat applies them over class defaults.
  • Tables sort on the client, over returned rows only. Matrix sends one query per subtotal depth, each with and without the column group, so subtotals are true evaluations.
  • Slicers rebuild their controls only when style or field changes, and _updating stops control updates from publishing filters.

The warehouse visual

Key warehouse3d. It is the only visual that does not draw on a ChartHost: it hosts a Viewport3D, so ChartVisual does not apply and it implements ILumenVisual directly. It lives in Lumen.Visuals, which is why the viewer has it with no code of its own.

FileRole
WarehouseModel.csWarehouseLayout turns rows into world-space bounds and bay row totals, and does the ray pick. WarehousePalette holds the color bands, and the legend reads the same object, so the two cannot disagree. No UI, so the unit tests cover it.
WarehouseScene.csMeshBatch merges boxes of one color into frozen meshes of under 60,000 vertices. WarehouseScene builds the structure, heat, highlight and label models.
WarehouseVisual.csThe visual: queries, change detection, overlays, camera flights and mouse handling. WarehouseCamera is the orbit state.

Decisions worth keeping:

  • Two queries. The first is filtered and says what is visible. The second sets QuerySpec.Unfiltered, which makes ReportSurface.ComposeFilters add nothing, and it drives the layout. Otherwise a slicer on level 60 would drop that level to the floor. The unfiltered result comes from the engine's cache, and Update compares it by reference to skip the layout.
  • Update does the least it can. Layout runs when the rows or format change, the structure when the visible set or theme changes, the heat when the filter changes or the mode changes. A selection or a resize touches no geometry.
  • No WPF hit testing. IsHitTestVisible is false on the viewport, because Viewport3D hit testing walks triangles in managed code. WarehouseLayout.Pick tests the ray against bay row bounds, then the slots of rows it hit. The root grid has a transparent background so it gets the mouse.
  • Draw order matters. WPF does not sort transparency, and transparent pixels still write depth. Hence opaque colors before translucent ones in Heat, and the labels in the last ModelVisual3D. Translucent boxes do not sort among themselves, so a nearer open slot can hide a farther one.
  • The near plane follows the distance. The plan view uses a 14 degree lens from far away to look orthographic. With a fixed near plane the depth buffer could not separate the tiles from the floor.
  • Field of view is horizontal in WPF. WarehouseCamera.Ray derives the vertical extent from the aspect ratio.
  • Flights run on CompositionTarget.Rendering and detach when they end, on unload, and in Dispose, since that static event would otherwise keep a removed visual alive.
  • Selection keys. A location's key is its id, and a bay row's key starts with row. A location cross-filters on Location ID, a tile on Aisle plus Bay row, or on Aisle plus its Bays. The visual's own selection does not filter it, so IsInteractiveControl and the normal cross-filter path are all it needs.

WarehouseSample in Lumen.Connectors generates the data with a fixed seed. LQL has no context transition, so "bay rows over 70%" cannot be a measure over a row-level measure; the sample stores a Bay Row Band column and counts distinct bay row keys with it. Layout assumes at most two bays per bay row.

Change routing. OnChanged(dataAffecting) decides the scope: a layout change only re-places containers and redraws, while a data-affecting change requeries and rebuilds panes. Session.AfterChange compares model JSON to decide whether the Dataset must be rebuilt.

13. Undo model

CommandStack holds IReportCommands. There are two kinds:

  • Snapshot. Session.Edit(label, action) serializes the document, runs the action, and serializes again. Undo restores the before JSON into the same Doc instance. It's simple and universal, and costs a document's JSON per step, which is small since rows aren't in it.
  • SetBoundsCommand handles drags. Commands with the same gesture id merge, so a drag is one step. Moves write straight to definitions during the gesture, and RecordBounds records them afterward without re-running them.

After an undo, VisualDef objects are new instances. Never hold one across an edit. VisualContainer.Def looks the current one up by id for this reason. Session.Tables is outside undo: undoing an import removes the table from the model, and the rows stay in the dictionary.

14. The .lumen format

A ZIP archive:

EntryContent
report.jsonThe ReportDocument, without the model.
model.jsonThe SemanticModel.
data/<tableId>.colColumn count, then for each column its id and the ColumnIO payload. Binary.
thumbnails/page1.pngPreview of the current page at save. Skipped by autosave.

LumenFile.Save writes to a .tmp file, then deletes the target and moves the temp file into place. A crash between those two leaves only the .tmp, so it isn't fully atomic. File.Replace would close that window. Open refuses a SchemaVersion above 1, and a missing data entry leaves that table out, so its visuals report a missing field.

A report file is executable in one sense: SQL text and the connection string in it run on Refresh. Connection strings use Integrated Security and contain no passwords.

15. Extension recipes

Add a visual

  1. Subclass ChartVisual, or CartesianVisual if it has axes.
  2. Register it in VisualRegistry.Factories. Keys are stored in files, so never rename one.
  3. Add an icon to Ui.VisualIcons in Panes.cs. The gallery and the Insert tab index that dictionary directly, so a missing key throws at startup.
public sealed class BulletVisual : ChartVisual
{
    public override VisualCapabilities Capabilities => new VisualCapabilities
    {
        DisplayName = "Bullet",
        FormatType = typeof(ChartFormat),
        Roles =
        {
            new DataRole("values", "Value", RoleKind.Measure, 1, 1),
            new DataRole("target", "Target", RoleKind.Measure, 1, 1)
        }
    };

    protected override void Render()
    {
        // Measures arrive in well order, so 0 is the value and 1 the target.
        double value = U.Data.Measure(0, 0).AsDouble();
        double target = U.Data.Measure(1, 0).AsDouble();
        double scale = U.Size.Width / Math.Max(1, Math.Max(value, target));
        var bar = new Rect(0, 20, value * scale, 24);

        using (var dc = Chart.MarksLayer.RenderOpen())
            dc.DrawRectangle(Frozen.Brush(Host.ColorFor("value")), null, bar);

        Marks.Add(new Mark
        {
            Bounds = bar,
            Tip = new List<TooltipItem> { new TooltipItem("Value", value.ToString("#,0")) }
        });
    }
}

// VisualRegistry.Factories
{ "bullet", () => new BulletVisual() },

// Ui.VisualIcons: a 16 by 16 path
{ "bullet", "M1,6h14v4H1z" },

Override BuildQueries only if the default doesn't fit. The default in ChartVisual turns Grouping wells into GroupBy and the others into measures, in one spec.

Add an LQL function

  1. Add a case to CompileCall in LqlCompiler.cs. Use Arity for argument counts.
  2. Add it to MeasureWindow.Functions for completion.
  3. Add it to Lql.xshd for highlighting.
  4. Add a test with a value computed independently.
case "SQRT":  return Numeric(n, s, Math.Sqrt);   // existing
case "LOG10": return Numeric(n, s, Math.Log10);  // new

Add a data source

  1. Write a reader that returns a ColumnBatch, honors the CancellationToken, and uses the builders in Columns.cs. TypeInference handles text sources.
  2. Add a case to TableLoader.ReadSource.
  3. Add a menu item with gi(...) in MainWindow.BuildRibbon, and call ImportSource with a DataSourceRef of your kind.

Add a transform step

  1. Add a constant to StepKinds.
  2. Add a case to TransformEngine.Apply. Read arguments from the step, and return a new ColumnBatch.
  3. Add a button in TransformWindow that calls Add(StepKinds.Create(kind, label, "key", value, ...)).

Add a format option

Add an attributed property to the format class and read it in Render. The editor appears automatically, and old files keep the default.

16. Tests and self-checks

tests/Lumen.Engine.Tests has 24 xUnit tests, all passing. Expected values come from a plain LINQ walk over the same rows, so the engine isn't checked against itself. Two fixtures exist: 20,000 rows for the serial paths, and 400,000 rows to cross the parallel threshold of Par.Chunk * 2. Anything that branches on size needs a test on the large fixture.

Coverage is engine, LQL, CSV, transforms, column serialization, the command stack, and the warehouse layout, picking and camera math. UI is covered by the --screenshot and --warehouse self-checks, not by unit tests.

The --screenshot self-check

MainWindow.RunScreenshot drives the real shell: all sample pages, cross-highlight, slicer, undo, each visual selected, every visual type, copy, paste and align, CSV and JSON import, measure, transform and SQL windows, SQL import, save and reopen, Dark and High contrast, and PDF. If the machine has been idle for 30 seconds, RealInputCheck injects real mouse input with mouse_event to test OLE drag and drop and canvas gestures, since WPF's drag loop ignores simulated events. Unhandled exceptions are collected in App.Failures, and fail the run.

The SQL portion expects local SQL Server instances, which are specific to the development machine. Its failures should be read accordingly.

What has not been exercised

These paths exist but were not run: Excel import, printing, Power BI theme import, clicking through Edit interactions, crash recovery, and opening the database drop-down with a real mouse (the list itself was tested). Check them first when something looks wrong there.

Traps

  • Results are shared. The cache returns the same instance to every caller. Don't mutate a QueryResult.
  • UI-thread queries. FiltersPane.BasicEditor runs one synchronously.
  • Autosave is synchronous, so a large model pauses the UI every 2 minutes while dirty.
  • Relative date filters resolve "today" when the query runs, but cached results can outlive midnight.
  • Deleting a table leaves visuals pointing at it. They report a missing field by design.
  • Between slicer detects its first build from Slider default values.
  • Table sort is client-side, over at most 3,500 rows, so a truncated result sorts the truncated set.
  • Cross-filter with several columns becomes per-column filters, not tuple matches, so selecting (A, 1) and (B, 2) also matches (A, 2).
  • Name clashes. Lumen.Engine.Encoding clashes with System.Text.Encoding, and Lumen.Model.Condition with System.Windows.Condition. Qualify them.
  • Build warning. MainWindow.Icon(string, double) hides Window.Icon (CS0108). It's harmless.
